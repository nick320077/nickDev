# ОСНОВА — первая версия магазина строительных материалов

Интернет-магазин на **Next.js 16 (App Router), TypeScript, React и PostgreSQL**. Собственный адаптивный дизайн, украинский интерфейс и цены в гривнах. «ОСНОВА» — рабочее название, которое можно заменить на ваш бренд.

## Что уже работает

- Главная страница с категориями и подборкой материалов.
- 12 демонстрационных товаров в 6 категориях.
- Страницы товаров с изображениями, описанием, артикулом, наличием и характеристиками.
- Поиск по названию, бренду и артикулу; фильтры по категории, бренду, максимальной цене и наличию; сортировка по цене и названию.
- Корзина: добавление, изменение количества от 1 до 99, удаление и пересчёт суммы. Сохранение в localStorage и синхронизация между вкладками.
- Мобильная и настольная версии, состояния пустого поиска и корзины, 404 и ошибки подключения.

**Реальные платежи, оформление заказов, учётные записи и доставка не подключены.** Товары, цены, наличие и характеристики демонстрационные. Изображения сгенерированы специально для прототипа и не являются фотографиями реальных товаров. Для похожих демо-товаров повторно используется изображение соответствующего типа материала.

Структура каталога и карточек вдохновлена [референсом](https://kub.in.ua/ua/), но код, логотип и фирменные изображения референса не использованы.

## Быстро посмотреть в браузере — без PostgreSQL

Требуются Node.js **22.13+** и npm.

```bash
git clone https://github.com/nick320077/nickDev.git
cd nickDev
git switch feat/storefront-mvp
npm ci
npm run dev
```

Откройте **http://localhost:3000**. При отсутствии `DATABASE_URL` магазин использует локальный демо-каталог из `src/lib/demo.json`; сервер базы данных для этого способа просмотра не нужен. Если `.env.local` уже создан, удалите из него `DATABASE_URL` или задайте пустое значение для демо-режима.

Для просмотра на смартфоне в той же локальной сети откройте `http://IP-вашего-компьютера:3000`. Сервер слушает `0.0.0.0`; доступ может зависеть от настроек локального брандмауэра.

Если запускаете в удалённой среде или Codespaces, откройте её раздел Ports / Порты и адрес предпросмотра порта **3000**. `localhost` на вашем компьютере не ведёт автоматически к серверу в удалённом окружении.

## Запуск с PostgreSQL

Требуются Docker и Docker Compose либо существующая PostgreSQL.

```bash
cp .env.example .env.local
docker compose up -d --wait
npm run db:seed
npm run dev
```

После этого также откройте **http://localhost:3000**. Compose запускает PostgreSQL 17; порт БД доступен только на `127.0.0.1`, данные хранятся в именованном томе. Пользователь и пароль `store` предназначены только для локальной разработки. Для существующей БД укажите её строку подключения в `.env.local` и выполните `npm run db:seed`.

Seed создаёт таблицу `products` и добавляет демонстрационные данные в транзакции. Повторный запуск обновляет существующие демо-товары по ID; не запускайте его на базе реального каталога. Для первой версии товары хранятся как JSONB с первичным ключом, порядком отображения и ограничением положительной цены. Сервер читает каталог через `pg`; строка подключения никогда не отправляется в браузер. Если `DATABASE_URL` задан, ошибка БД отображается как ошибка, без скрытого перехода на локальные данные.

Для остановки локальной БД: `docker compose stop`. `.env.local` игнорируется Git; реальные пароли в репозиторий не добавляйте.

## Проверки

```bash
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты автоматически запускают production-сервер после сборки и проходят на настольном и мобильном экранах. Проверяются поиск, совместная работа фильтров, карточка, изменение количества и суммы, восстановление корзины, удаление, недоступный товар, 404 и отсутствие горизонтального переполнения. При заданной `DATABASE_URL` отдельный тест временно изменяет демо-товар в PostgreSQL, проверяет его отображение на сайте и восстанавливает данные.

Если Chromium установлен в системе, можно указать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium` вместо скачивания браузера. На Windows используйте подходящий синтаксис переменных окружения для вашей оболочки.

Для production-просмотра: `npm run build`, затем `npm run start`. Публичное размещение сайта в рамках этого этапа не выполняется. GitHub Actions проверяет lint, типы, unit-тесты, сборку и браузерные сценарии с PostgreSQL.

## Второй вариант дизайна: товар в главной роли

Ветка `feat/product-main-character` содержит второй вариант **всего магазина**: главная с товарной сценой вместо абстрактного баннера, подборка материалов перед категориями, каталог с предметной подачей и альтернативная композиция всех страниц товаров. На страницах товаров: крупная предметная сцена, палитра по категории, отдельный блок покупки, краткое назначение и подробные характеристики ниже. Исходный вариант остаётся в `feat/storefront-mvp`.

```bash
git fetch origin
git switch feat/product-main-character
npm ci
npm run dev
```

Откройте любой товар в каталоге, например `/products/plaster-30` или `/products/primer-10`. Утверждённое изображение мешка на пьедестале сохранено без изменения в `public/products/warehouse-bag.png`; другие типы материалов используют общий фон и собственное изображение предмета. Сцена склада и сотрудники — художественная сгенерированная визуализация, а не описание фактического склада или обслуживания. Пока используются демонстрационные изображения, включая общие изображения для похожих типов материалов.

### Шрифт

Во втором дизайне используется **Manrope**: локальный вариативный шрифт с поддержкой украинского алфавита и символа гривны. Заголовки получили более спокойные интервалы, цены — табличные цифры, длинные названия товаров могут занимать дополнительные строки. Шрифт включён в репозиторий вместе с лицензией SIL OFL и загружается с самого сайта без обращения к Google Fonts. Дополнительная установка пакетов не нужна.
